# thread-context — 다른 스레드의 맥락 가져오기

사용자가 **다른 스레드를 제목·멘션·링크로 가리키며** 그 내용을 참고하라고 할 때 쓴다.
조회 전용이다. 상대 스레드에 글을 쓰거나 상대 세션에 작업을 시키지 않는다.

도구: `T=~/.claude/skills/thread-context/thread_lookup.py`

| 명령 | 용도 |
|---|---|
| `python3 $T find "<제목 일부 또는 <#id>/링크>"` | 스레드 후보 (JSON 줄: id·title·archived·live_session) |
| `python3 $T history <thread_id> --limit 20 [--before <msg_id>] [--max-chars 500]` | 기록 읽기(오래된→최신, 메시지당 잘라냄) |
| `python3 $T sessions` | 스레드에 묶인 살아 있는 tmux 세션 목록 |

조회·줄 형식의 정본은 discord-handoff `handoff_lib.py history`(`fetch_history`)이며 이 명령은 그것을 부른다. 첨부는 파일명+URL로 나오고, 기본 `--max-chars 500`은 이 명령만의 기본값이다.
이 스킬은 같은 저장소의 discord-handoff 에 의존한다. 제목 검색에는 `DISCORD_GUILD_ID` 환경변수(서버 ID)가 필요하고, `<#id>`·링크로 찾을 땐 필요 없다.

## 절차

### 1. 스레드 특정
- 사용자 문장에 `<#숫자>` 또는 `discord.com/channels/…/<id>` 가 있으면 그 id 를 그대로 쓴다.
- 없으면 제목 표현으로 `find` 한다. `find` 는 7초쯤 걸린다(보관 스레드까지 훑음).
  - 후보 1개 → 진행
  - 후보 여럿 → **제목 목록을 보여 주고 되묻는다** (추측해서 고르지 마라)
  - 0개 → 다른 표현으로 한 번 더 찾아보고, 그래도 없으면 사용자에게 링크를 달라고 한다

### 2. 세션이 살아 있으면 → 직접 묻는다 (우선)
`find` 결과의 `live_session` 이 `agent-<thread_id>` 면 그 스레드의 Claude 세션이 이 머신에 떠 있다.
그 세션은 자기 전체 맥락(실행한 명령·읽은 파일·결정 경위)을 갖고 있어서 원문을 읽는 것보다 정확하다.

1. `ToolSearch("select:ListAgents,SendMessage")` 로 도구를 불러온다. 이 도구들이 없는 Claude Code 환경이면 3단계로 간다.
2. `ListAgents` 에서 `tmux agent-<thread_id>:` 가 붙은 행을 찾는다. 이름이 겹치면**` [ref]` 까지 붙여** 보낸다.
   - 그 행이 `busy` 면 끼어들지 말고 3단계(기록 읽기)로 간다. 사용자가 꼭 그 세션 답을 원하면 보내 두고 기다린다.
3. 질문은 구체적으로, 답은 짧게, 회신 경로를 명시해서 보낸다:
   ```
   [thread-context 문의 — 조회만, 작업 요청 아님]
   보낸 쪽: <내 세션 이름(ListAgents 맨 위 "This session is ...")>, 스레드 "<내 스레드 제목>"
   질문: <예: 이 스레드에서 X 에 대해 결정된 것·현재 상태·남은 일을 10줄 이내로>
   답은 디스코드에 올리지 말고 SendMessage 로 위 세션에게만 보내 주세요. 파일 수정은 하지 마세요.
   ```
4. 답이 오면 **출처를 밝혀** 사용자에게 전달한다 (「"<스레드 제목>" 세션 답변: …」).
5. 몇 분 안에 답이 없으면 기다리지 말고 3단계로 대체하고, 그 사실을 말한다.

### 3. 세션이 없거나 바쁘면 → 기록을 읽는다
- `history <id> --limit 20` 부터. 부족하면 가장 오래된 `msg=` 값을 `--before` 로 넘겨 더 읽는다.
- 긴 보고서는 `--max-chars` 를 늘려 해당 구간만 다시 읽는다. 처음부터 통째로 읽지 마라.
- `(bot)` 표시된 상태 안내(🔧 부르는 중, 📥 요청 받았어요, 진행 표시)는 무시한다.
- 읽은 내용은 요약해서 출처(스레드 제목·대략적 시각)와 함께 전달한다.

## 금지
- 상대 스레드에 메시지를 쓰지 않는다 (`handoff_lib.py send --target <상대 id>` 금지).
- 상대 세션에 작업(파일 수정·커밋 등)을 요청하지 않는다. 질문·답만.
- 상대 세션에 같은 질문을 반복 전송하지 않는다 (한 번 보내고 기다리거나 기록 읽기로 대체).
- 이 스킬은 일회성 참조용이다.
